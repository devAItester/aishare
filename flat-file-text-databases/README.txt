FLAT-FILE TEXT DATABASES

Цель
  Эксперимент: хранить небольшую базу знаний как дерево каталогов и обычные
  текстовые файлы. Навигация выполняется из терминала. Важная часть эксперимента
  — не только дерево каталогов, но и формат самих текстовых записей.

Принцип
  каталог = уровень классификации
  файл.txt = одна законченная тема
  пробелы = вложенность внутри файла
  пустая строка = граница записи
  ключ: значение = простое поле
  текст после поля = свободное содержание

Как работать
  1. Перейди в корень базы:
     cd ~/aishare/flat-file-text-databases

  2. Посмотри дерево:
     tree

     Если tree не установлен:
     find . -type f -o -type d

  3. Перейди к нужному уровню обычным cd:
     cd 01-it/02-dev/03-linux/04-arch/05-niri

  4. Прочитай файл без редактора:
     cat shortcuts.txt

  5. Для длинного файла:
     less shortcuts.txt

  6. Ищи по всей базе:
     grep -Rni 'ssh' .

  7. Ищи только в txt:
     grep -Rni --include='*.txt' 'ssh' .

  8. Найди все заголовки:
     grep -Rni '^title:' .

  9. Получи список файлов:
     find . -type f -name '*.txt' | sort

  10. Найди записи с конкретным ключом:
      grep -Rni '^  status:' .

Формат записи
  title: короткое имя темы
  status: draft | tested | reference
  date: YYYY-MM-DD
  tags: tag1, tag2

  section:
    subsection:
      fact: проверяемое утверждение
      practice: практический способ
      tradeoff: компромисс
      check: как проверить результат

Правило отступов
  0 пробелов  = корневые поля
  2 пробела   = раздел
  4 пробела   = подраздел или запись
  6 пробелов  = поле записи
  8 пробелов  = продолжение значения

Не использовать Markdown-разметку как обязательную часть формата.
Заголовок файла уже задаёт адрес записи, поэтому внутри файла достаточно
простых полей и пробельной иерархии.

Минимальная проверка формата
  grep -Rni $'^[[:space:]]' .
  grep -Rni '^title:' .
  grep -Rni '^status:' .

Экспериментальная гипотеза
  Если классификации каталогов достаточно, чтобы быстро сузить область поиска,
  а пробелы внутри txt достаточно однозначны для человека и простых скриптов,
  отдельный формат базы данных не нужен для небольшого личного корпуса.

Ограничение
  GitHub удобен как транспорт и история изменений, но эта структура не делает
  Git файловой СУБД. Индексация и поиск остаются задачей файловой системы,
  grep/awk/sed или отдельного небольшого инструмента.
