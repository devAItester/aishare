Формирование отображения страницы в браузере может происходить двумя путями:
Когда HTML сформирован на сервере, и тогда браузеру все что нужно сделать это интрепреировать HTML

И когда HTML формируется у вас в самом браузере, путем выполнения JS логики. Тогда бразеру нужно выполнить JS локигу, получить HTML и интерпретировать HTML


Один из, случаев когда это имеет значение - это случай индиксации (получения информации) о нашем проекте поисковой системой.

Очевидно, что в случае HTML ей нужно только взять статичный файл, и извлеч из него все что ей нужно.

В случае когда результирующее отображение формируется JS кодом, нужно не просто взять исходный HTML но и выполнить JS код, который сформирует отображение, которое и будет индексировать бот.

Number.isNaN( "lorem" ); //false

В отличие от глобальной функции isNaN⁽¹⁾, которая выполняет неявное преобразование аргумента к числу перед проверкой на NaN, метод Number.isNaN⁽²⁾ осуществляет строгую проверку без приведения типов. Данное различие в семантике делает Number.isNaN типобезопасным предикатом, возвращающим true исключительно для числового значения NaN.

Пример:
// Различие в семантике преобразования
isNaN("NaN")         // true (после преобразования "NaN" → NaN)
Number.isNaN("NaN")  // false (строгая проверка без преобразования)

// Типобезопасная проверка
isNaN(undefined)     // true (неявное преобразование)
Number.isNaN(undefined) // false (сохранение типа)


Примечания:
1. 19.2.3 isNaN ( number ) — https://tc39.es/ecma262/2024/multipage/global-object.html#sec-isnan-number

Number.isNaN это метод который, появилися относительно недавно и реализован в соответствии с рекомендацией спецификацией IEEE754:

Перед нами должно быть float point datum
В противном случае false
Если этот datum находится в диапазоне множества значений NaN - тогда true


Глобальный же isNaN сущестсовал с 1997 года, и почему он был сделан именно так - я не знаю. Могу только предположить, что:

В 1997 году, JS позиционировался как надстройка над JAVA для того чтобы человек с невысокой квалификацией мог быстро набросать какой-нибудь нужный ему код.

В исходниках V8 найдено несколько фрагментов, связанных с определением и реализацией проверки NaN, в том числе для Number.isNaN() и обычного isNaN(). Вот ключевые детали и анализ различий:

---

### Реализация и описание Number.isNaN()

Внутри движка V8 основная проверка на NaN сводится к использованию стандартной функции std::isnan() (C++), либо к сравнению значения с самим собой (NaN !== NaN):

- В файле [src/objects/objects-inl.h](https://github.com/v8/v8/blob/034b5c66fab3d37d4de49b4a6b785b6f83f849a7/src/objects/objects-inl.h#L782-L871) реализовано:
  // static
  bool IsNaN(Tagged<Object> obj) {
    return IsHeapNumber(obj) && std::isnan(Cast<HeapNumber>(obj)->value());
  }

Этот код проверяет, что объект — это число с плавающей точкой (HeapNumber), и только тогда вызывает std::isnan.

- Внутри [src/compiler/node-matchers.h](https://github.com/v8/v8/blob/034b5c66fab3d37d4de49b4a6b785b6f83f849a7/src/compiler/node-matchers.h#L184-L261):
  bool IsNaN() const {
    return this->HasResolvedValue() && std::isnan(this->ResolvedValue());
  }

То есть, строгое сравнение только для чисел.

---

### Реализация и описание простого isNaN()

- В большинстве реализаций движка, например [src/execution/s390/simulator-s390.h](https://github.com/v8/v8/blob/034b5c66fab3d37d4de49b4a6b785b6f83f849a7/src/execution/s390/simulator-s390.h#L281-L358):
  bool isNaN(double value) { return (value != value); }

Это стандартная проверка на NaN: только NaN не равно самому себе.

Однако, простая функция isNaN в спецификации JavaScript (и так реализована в V8) сначала приводит аргумент к числу (Number(value)), а затем уже делает проверку на NaN.

---

### Отличия Number.isNaN() и isNaN()

#### 1. Number.isNaN()
- Не приводит аргумент к числу, проверяет тип.
- Возвращает true только если аргумент — именно NaN и тип аргумента — Number.
- Пример: 
  Number.isNaN(NaN);        // true
  Number.isNaN("foo");      // false
  Number.isNaN(undefined);  // false
  Number.isNaN("123");      // false


#### 2. Обычный isNaN()
- Сначала приводит аргумент к числу, затем проверяет на NaN.
- Может возвращать true для значений, которые не являются NaN, но после приведения становятся NaN.
- Пример:
  isNaN(NaN);        // true
  isNaN("foo");      // true  ("foo" -> NaN)
  isNaN(undefined);  // true  (undefined -> NaN)
  isNaN("123");      // false ("123" -> 123)


---

### Внутренние детали V8

- Number.isNaN() реализуется через строгую проверку на NaN без преобразования типов.
- Обычный isNaN() сначала вызывает преобразование к числу, затем сравнивает с NaN.

---

#### Итог:
- Number.isNaN(x) — строгое сравнение и проверка типа, возвращает true только для значения NaN типа Number.
- isNaN(x) — сначала приводит аргумент к числу, затем проверяет на NaN, что может давать true на неожиданных типах.

WASM окончательно перестал быть чем-то, что можно было рассматривать (хотябы потенциально), как низкоуровневую замену JavaScript

И продолжил двигаться в сторону создания инструмента удобной транскопиляции из языков не поддерживаемых в WEB в язык который их поддерживает.

WASM 3.0 - это не инструмент для программирования. Это инструмент для эффективного создания инструментов для транскомпиляции кода из других языков в код, который можно исполнять в браузере.

WASM 3.0 чем дальше тем больше теряет свою возможность быть прогнозируемым (с точки зрения времени исполнения кода) инструментом, но приобретает возможности для простого преобразования кода из одного языка в другой.

По сути, генерируется новый JavaScript с синтаксисом в который легко преобразовать любой другой синтаксис.
