Асинхронность в программировании — это когда программа не ждёт, пока одна задача полностью закончится, чтобы начать другую. Она может делать несколько дел «параллельно» (или почти параллельно), не застревая на ожидании.

### Простой пример из жизни

Представь, что ты готовишь борщ:

Синхронный способ (обычный, «по очереди»):
1. Ставим кастрюлю с водой на плиту.
2. Стоим и ждём 15 минут, пока вода закипит (ничего больше не делаем!).
3. Кидаем картошку.
4. Снова стоим и ждём 10 минут.
5. Режем капусту… и так далее.

Ты тратишь кучу времени просто на ожидание.

Асинхронный способ:
1. Ставим кастрюлю с водой на плиту.
2. Пока вода закипает — идём и чистим картошку, режем морковку, моем свёклу.
3. Как только вода закипела — бросаем картошку и продолжаем резать остальное.
4. Всё готовится, а ты в это время занимаешься другими делами.

Ты не теряешь время на ожидание — используешь его с пользой.

### В программировании то же самое

Часто программа должна ждать: ответа от сервера, загрузки файла, ввода от пользователя и т.д. Если ждать «синхронно» — вся программа просто замирает (как будто ты стоишь у плиты и смотришь на воду).

Асинхронность позволяет:
- Запросить данные с сервера
- И пока они грузятся — продолжать работать: рисовать интерфейс, обрабатывать клики, показывать анимации и т.д.
- Как только данные пришли — сразу их обработать

### Как это выглядит в коде (очень упрощённо)

Синхронно (программа застрянет на 5 секунд):
console.log("Начинаю загрузку...");
let data = ждём_ответ_от_сервера(); // ← здесь программа просто стоит 5 секунд
console.log("Данные пришли!", data);

Асинхронно:
console.log("Начинаю загрузку...");
ждём_ответ_от_сервера_асинхронно().then(data => {
  console.log("Данные пришли!", data); // выполнится, когда придут
});
console.log("А я пока продолжаю работать!"); // ← это выведется сразу

### Где это используют
- Загрузка картинок, видео, данных из интернета
- Работа с файлами
- Чат-приложения (сообщения приходят в любой момент)
- Игры, анимации — чтобы интерфейс не зависал

### Главная идея простыми словами
Асинхронность — это умение программы «не стоять столбом» в ожидании, а заниматься другими делами, пока что-то долго выполняется.

Мелкомягкие не просто смешали а чётко разделили два уровня: сами объекты задач (Task'и), которые лишь описывают выполняемую работу, и инфраструктуру, которая эту работу исполняет. Создание Task само по себе ничего не запускает и фактическое выполнение происходит тогда, когда задача передаётся планировщику, чаще всего ThreadPool'у. Он берёт свободный заранее подготовленный поток который создала ОС, выполняет в нём задачу и после завершения этот отработанный поток снова возвращается обратно в пул.

И в итоге модель выглядит так:
Задача создаётся -> Планировщик помещает её в пул потоков -> Один из потоков пула выполняет её -> Поток освобождается , возвращает в PoolThread и продолжает обслуживать следующие задачи .

Ну и с асинхронностью в C# работает похожий принцип: async/await — это синтаксический сахар, который позволяет писать асинхронный код "как синхронный", не блокируя поток при выполнении. Когда ты делаешь await на задачу, текущий поток освобождается и может выполнять другие задачи, а продолжение (continuation) зарегистрированной задачи будет выполнено, когда асинхронная операция завершится, зачастую без создания нового потока, особенно для операций ввода-вывода. Таким образом, асинхронность отделена от потоков: Task описывает работу, ThreadPool или системные механизмы управляют потоками, а async/await управляет продолжением выполнения.

Поэтому как видите асинхронные функции, объекты тасков и потоков работают здесь в одном общем симбиозе с разными "инфраструктурами)"

// та ж сама функція, але з async
async function heavyComputation() {
 /* heavy, yet still syncronous computations */

const promises = []

  promises.push(heavyComputation())
}
const results = await Promise.all(promises)
