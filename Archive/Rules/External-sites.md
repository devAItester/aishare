# Проверка внешних сайтов и исходников

## Что использовать

Для опубликованных страниц сайта Давида я в этой проверке использовал инструмент **`web.run`**, выполнив операцию **`open`** с URL страницы. Это вернуло извлечённый текст страницы и ссылки, но **не сырой HTML-код**.

Не называй извлечённый текст «исходником страницы». Это разные результаты:

- **`web.run` → `open`** — открыть URL и получить доступное представление содержимого страницы.
- **Сырой HTML** — исходный ответ документа, включая разметку; отдельно подтверждай, что действительно получил именно его.
- **CSS** — таблица стилей, подключённая к странице; сначала установи её настоящий URL по доступным данным страницы, затем попробуй открыть этот URL.
- **GitHub connector / tools** — получить файлы, исходный код, конфигурацию и историю репозитория.
- **Визуальная проверка в браузере** — сравнение реально отрисованных страниц; не утверждай, что выполнил её, если фактически не сравнивал отображение.

## Порядок проверки

1. Открой опубликованную страницу через `web.run` с операцией `open`.
2. Установи, какие именно данные получены: текст страницы, ссылки, сырой HTML или CSS.
3. Если нужны HTML или CSS, а их не удалось получить, попробуй другие доступные способы и источники. Не останавливайся после первой ошибки.
4. Для связанных исходников ищи официальный репозиторий и используй GitHub connector / tools или GitHub API.
5. Сопоставляй исходники с опубликованным поведением, но не выдавай чтение кода за визуальную проверку.
6. В отчёте перечисляй, что проверено, каким конкретно инструментом и что осталось непроверенным. Не утверждай, что сайт недоступен, только потому что один способ не сработал.

## Короткая команда

> Проверь опубликованный сайт через доступные инструменты. Для начала используй `web.run` с операцией `open`; не называй полученный текст сырым HTML. Если нужны исходный HTML или CSS, попробуй другие доступные способы и официальный репозиторий. Для GitHub используй GitHub connector / tools или GitHub API. Чётко укажи, что именно удалось получить и что фактически проверено.
