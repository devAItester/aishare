# Один источник данных, несколько представлений.

Структура должна оставаться понятной в текстовом редакторе, терминале и на GitHub. Генератор помогает собрать публикацию, но не должен быть единственным местом, где устройство системы имеет смысл.

Материалы сайта находятся в `pages/`. Папки и вложенные папки формируют иерархию меню. Для папки не нужен `index.md`: её основная страница называется так же, как папка (например, `pages/01-project/01-project.md`), а её `permalink` задаёт адрес пункта меню. Остальные страницы остаются в той же папке. Корневая `pages/index.md` — главная страница сайта, а не обязательный индекс каждого раздела.

## Разделение ответственности

| Слой | Где хранится | За что отвечает |
|---|---|---|
| Основное содержимое | Markdown-файл в `pages/` | Единственный источник текста страницы |
| Физическая организация | Путь файла | Структура исходников и автоматическая иерархия меню |
| Метаданные | Front matter страницы | Заголовок, описание, `permalink` и свойства самой страницы |
| Публичный адрес | Front matter: `permalink` | Стабильный URL, независимый от пути и тематических связей |
| Представления | Liquid-шаблоны и правила выборки | Меню, списки страниц и связанные материалы |
| Общая оболочка | `_layouts/default.html` | Общая HTML-структура |
| Оформление | `assets/main.css` | Визуальные правила |
| Сборка | Jekyll / GitHub Pages | Преобразование исходников в статические HTML-файлы |
| Исходный архив | `Archive/` | Исторические материалы; не является зависимостью сайта |

## Меню из структуры каталогов

Меню строится шаблоном `_includes/folder-navigation.html` по путям страниц из `site.pages`. Ручной список пунктов в `_data/navigation.yml` не используется.

Правила:

1. Каждая папка внутри `pages/` образует пункт меню; вложенные папки становятся вложенными пунктами.
2. Основная страница папки называется так же, как папка: для `pages/01-project/` это `01-project.md`, не `index.md`.
3. Ссылка пункта ведёт на `permalink` этой основной страницы. Если одноимённого файла нет, пункт меню для этой папки не выводится: случайная страница не подменяет главную.
4. Подпись пункта берётся из `title` выбранной страницы.
5. `permalink` сохраняет публичный URL независимо от перемещения или переименования исходного файла.
6. `Archive/` исключён из источников навигации и не влияет на меню.

Категории и теги можно в будущем использовать для сквозных тематических подборок, но они не нужны для формирования основного меню и сейчас им не управляют.

## Что здесь от Jekyll, что от Oscean, а что от нас

**Jekyll — механизм сборки.** Он преобразует Markdown, использует YAML-данные и Liquid-шаблоны, а на выходе создаёт статические HTML-файлы.

**Oscean Дэвида — исследуемый референс.** У него изучаются визуальный язык, организация страниц, многоуровневая навигация, смысловые связи и поведение интерфейса. Текущая версия ещё не является точной копией оригинала; меню по каталогам реализовано отдельным Liquid include и требует проверки сборкой и в браузере. См. [визуальный язык и проверку соответствия](styling.html).

**Наши архитектурные решения** — разделение ответственности, единый источник содержимого, явные метаданные, низкая связность и минимально достаточная сложность. Это принципы, применённые к проекту, а не автоматические свойства Jekyll или Oscean. См. [HowProgrammingWorks: Principles](https://github.com/HowProgrammingWorks/Principles).

## Поток сборки

```text
Markdown + front matter + HTML/Liquid + CSS
                    |
                  Jekyll
                    |
            статические HTML-файлы
                    |
         браузер: HTML + CSS + ссылки
```

## Граница архива

`Archive/` — независимое хранилище исходных материалов. Оно не участвует в меню, тематических представлениях или сборке сайта. Сайт хранит собственное содержимое и метаданные.
