И так в функции есть как минимум два места для оптимизации - локальный или глобальный.

1. Локальный способ. В оригинальной функции есть два вложенных цикла и .indexOf. реализацию в в8 не смотрел, так же как и спеку indexOf, но подозреваю что там так же само итеративно ищется индекс до первого вхождения искомого value. В псевдо биг-О нотации О(arr1.length*arr2.length*k), где k - .indexOf итерации.
Локальная оптимизация заключается в использовании new Set и приводит к сокразению количества итераций до О(arr1.length*arr2.length) - удалось избавится от к
function findCommonElementsWithSet(arr1, arr2) {
    var commonElementsSet = new Set();

    for (var i = 0; i < arr1.length; i++) {
      for (var j = 0; j < arr2.length; j++) {
        if (
            arr1[i] === arr2[j] 
        ) {
            commonElementsSet.add(arr1[i]);
        }
      }
    }
    return commonElementsSet
}

Тест делался на в хроме через index.html
// arr1, arr2 длинна 30_000, диапазон чисел от -100_000 до 100_000.
// Всего 6 итераций и откидывается первая для исключения помех.
// Function findCommonElements need 1.463 sec
// Function findCommonElementsWithSet need 1.271 sec
Результат стабильный

2. Глобальная оптимизации заключается в полном изменении подхода. Вложенные итерации исключаются. 
function findCommonElementsWithMapNaive(arr1, arr2) {
    var commonElementsMap = new Map();

    for (var i = 0; i < arr1.length; i++) {
        commonElementsMap.set(arr1[i], false)
    }
    for (var j = 0; j < arr2.length; j++) {
        commonElementsMap.has(arr2[j]) && commonElementsMap.set(arr2[j], true)
    }
    
    const iterator = commonElementsMap.entries();

    var result = [];
    for (var k = 0; k < commonElementsMap.size; k++) {
        var value = iterator.next().value;
        
        value[1] === true && result.push(value[0]);
    }

    return result;
}

Вводные те же
// Function findCommonElementsWithMapNaive need 0.002 sec
Для 1_000_000 елементов в обоих массивах 0.073 - 0.091 seс
В псевдо биг-О O(n+k+l)
Драматическое улучшение.

В красивости и правильности findCommonElementsWithMapNaive не уверен, но тут цель показать подход
