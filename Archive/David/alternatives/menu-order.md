# Варианты задания порядка пунктов меню

## Решение

**Выбранный вариант для нашей Jekyll-реплики: необязательный служебный файл `_menu` внутри того каталога, порядок страниц которого нужно настроить.**

Пример:

```text
development/
    _menu
    tests.md
    navigation.md
    path-and-url.md
```

Содержимое `development/_menu`:

```text
tests.md
navigation.md
```

Перечисленные страницы идут первыми в указанном порядке; остальные страницы того же каталога добавляются после них в алфавитном порядке. Если `_menu` отсутствует, используется алфавитная сортировка. Сам `_menu` — метафайл без расширения, не публичная страница.

## Почему выбран этот вариант

- **Локальность:** правило порядка находится рядом с файлами, на которые оно влияет.
- **Минимум дублирования:** файловое дерево остаётся источником структуры; отдельный реестр нужен только для исключений порядка.
- **Низкая стоимость сопровождения:** новая страница автоматически попадает в алфавитный хвост; вручную перечислять всё содержимое каталога не требуется.
- **Читаемость:** обычный текстовый список без YAML-синтаксиса и числовых полей в front matter.
- **Без переименования страниц:** порядок не требует добавлять номера или префиксы к публичным именам файлов.
- **Без правки шаблона при каждом изменении:** автор меняет только локальный список порядка, когда это действительно нужно.

Это осознанное отличие от Oscean: в оригинале порядок получается из lexicon/структуры терминов, отдельного файла `_menu` для этого нет. В Jekyll-реплике локальный metafile — простой способ выразить редакторское исключение, не превращая его в глобальную модель навигации.

## Рассмотренные технические варианты

| Вариант | Преимущества | Недостатки | Оценка |
|---|---|---|---|
| Алфавитный порядок без дополнительных данных | Ничего не нужно поддерживать; новые страницы появляются автоматически | Нельзя выразить редакторский порядок, отличный от алфавита | Оставить как поведение по умолчанию, но не как единственный механизм |
| **Локальный `_menu` в нужном каталоге** | Правило рядом с контентом; затрагивает только один каталог; простой текст; не меняет URL и имена | Нужно проверять, что записи существуют и не повторяются | **Выбран** |
| Глобальный YAML/JSON-реестр, например `_data/menu.yml` | Все переопределения видны в одном месте; структурированный формат | Отдельный реестр дублирует часть структуры и разносит правило порядка от каталога; требует поддерживать пути/ключи | Не выбран для целевой схемы |
| Числовое поле порядка в front matter каждой страницы | Порядок можно хранить рядом с метаданными страницы | Добавляет служебные метаданные многим страницам; новые страницы требуют выбора номера; возможны коллизии и перенумерация | Не выбран |
| Числовые префиксы в именах файлов | Сортировка получается из имён без отдельного механизма | Загрязняет имена файлов и URL, если имена участвуют в permalink; перестановка требует переименований и обновления ссылок | Не выбран |
| Жёстко заданный порядок в Liquid/шаблоне | Не нужен отдельный файл данных | Контент и представление смешиваются; изменения требуют править шаблон; плохо масштабируется по каталогам | Не выбран |

## Что подтверждено историей репозитория, а что нет

Сохранённый GitHub-код подтверждает, что в `d00-jk` использовался глобальный вариант: `_data/menu.yml` задаёт `development: [tests.md, navigation.md]`, а `_includes/ordered-pages.html` читает `site.data.menu`. В репозитории также есть `development/_menu` с теми же строками, и документация описывает локальный формат. Следовательно, артефакты репозитория содержат оба варианта; наличие `_menu` само по себе не доказывает, что именно этот файл использует активный шаблон.

Поиск прежней переписки не восстановил полный перечень вариантов, которые обсуждались в чате. Поэтому таблица выше фиксирует технические альтернативы и их оценку, но не выдаёт каждый пункт за дословно подтверждённое историческое предложение. Подтверждённый исторический факт о глобальном YAML указан отдельно.

## Требования к реализации выбранного варианта

- Читать `_menu` только в соответствующем каталоге.
- Каждая запись — имя публичной страницы этого же каталога.
- Дубликаты и несуществующие страницы должны приводить к понятной ошибке проверки/сборки.
- Перечисленные страницы идут первыми в заданном порядке.
- Неперечисленные страницы идут после них в алфавитном порядке.
- Без `_menu` весь каталог сортируется по алфавиту.
- `_menu` не публикуется как страница сайта.
- Не считать механизм реализованным в конкретном репозитории, пока активный код и тесты не подтверждены.
