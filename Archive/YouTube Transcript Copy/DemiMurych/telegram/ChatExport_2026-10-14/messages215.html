Справа не в потоках (JavaScript у Node.js однопотоковий). Головна причина — різниця в буферизації:
console.log() та console.error() проходять через механізми Node.js. Коли ви перенаправляєте вивід у файл, Node.js починає буферизувати ці дані (збирає їх у пам'яті перед записом на диск для оптимізації).
%DebugPrint() — це низькорівнева C++ функція самого рушія V8. Вона повністю ігнорує інфраструктуру Node.js, нічого не буферизує і миттєво пише дані напряму в системний потік ОС.

Результат: %DebugPrint() записує свій дамп у файл миттєво, обганяючи текст від console.log(), який все ще «висить» у буфері Node.js.

Тому рядки змішуються.

Найкраще рішення:

Щоб вивід був строго послідовним, потрібно відмовитися від асинхронних буферизованих консолей і змусити Node.js писати логи синхронно та напряму у системні файлові дескриптори (stdout — 1, stderr — 2). Тоді ваш код працюватиме в тому ж ритмі, що й %DebugPrint().

Ось готовий, надійний скрипт:


JavaScript
const fs = require('fs'); // Пишемо напряму в стандартний вивід (дескриптор 1) синхронно function syncLog(msg) { fs.writeSync(1, msg + '\n'); } // Пишемо напряму у вивід помилок (дескриптор 2) синхронно function syncError(msg) { fs.writeSync(2, msg + '\n'); } const codeSnippets = [ "let a = 5; a + 10;", "throw new Error('Тестова помилка');", "let obj = { x: 1 }; obj;" ]; for (let i = 0; i < codeSnippets.length; i++) { const code = codeSnippets[i]; syncLog(\n--- [Сніпет ${i + 1}]: ${code} ---); try { const result = eval(code); // %DebugPrint тепер не обжене syncLog, бо обидва пишуть напряму %DebugPrint(result); } catch (error) { syncError(ПОМИЛКА: ${error.message}); } }



Як запускати, щоб усе записалося в один файл ідеально рівно:

У терміналі злийте потоки stdout (успішні логи та DebugPrint) та stderr (помилки) в один файл за допомогою 2>&1:

node --allow-natives-syntax script.js > output.log 2>&
