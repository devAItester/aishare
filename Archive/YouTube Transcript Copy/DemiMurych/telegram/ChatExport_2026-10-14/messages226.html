Смотри какое извращение есть:

Обычно для создания интерактивности мы используем JavaScript: объявляем переменную, вешаем слушатель событий на кнопку и обновляем DOM. Но в чистом HTML/CSS нет переменных в привычном понимании и нет слушателей кликов.

Чтобы обойти это, мы используем встроенную систему состояний HTML и систему счетчиков CSS.
Весь фокус держится на трех китах:

1. Память (Где мы храним счет?)
В CSS есть встроенный механизм нумерации (обычно он используется для создания автоматических списков вида «Глава 1», «Глава 2» и т.д.). Мы инициализируем этот счетчик в самом начале документа:
CSS
body {
  /* Создаем "переменную" clicks и задаем ей значение 0 */
  counter-reset: clicks; 
}

2. Состояние (Как мы фиксируем клик?)

Раз у нас нет событий вроде onclick, нам нужен HTML-элемент, который умеет "запоминать", что на него нажали. Идеальный кандидат — чекбокс. У него есть два строгих состояния: обычное и :checked. Сами чекбоксы мы прячем (display: none;), потому что они некрасивые. Вместо них мы показываем красивые элементы <label>, которые жестко связаны с чекбоксами через атрибуты id и for (или просто оборачивая чекбокс, но в сложных кликерах используют связь по ID). При клике по label невидимый чекбокс меняет состояние.

3. Логика (Как клик меняет счет?)
Вот здесь происходит главная магия. Мы пишем CSS-правило, которое срабатывает только если чекбокс нажат:
CSS
input[type="checkbox"]:checked {
  /* Если чекбокс активирован, увеличиваем наш счетчик на 1 */
  counter-increment: clicks;
}

4. Рендер (Как показать счетчик на экране?)
HTML не умеет сам забирать данные из CSS-счетчиков, поэтому мы выводим цифру с помощью CSS-псевдоэлемента ::after (или ::before). Свойство content умеет читать значение счетчика и рисовать его на экране:
CSS
.score::after {
  /* Берем текущее значение "переменной" clicks и выводим как текст */
  content: counter(clicks); 
}

Главная проблема: «Одноразовые» клики

Если ты посмотришь на код выше, то заметишь ограничение. Чекбокс можно перевести в состояние :checked только один раз (снять галочку — значит уменьшить счетчик, а нам это не нужно в кликере).
Пять чекбоксов в коде дадут максимум 5 очков. Как сделать кликер бесконечным (или хотя бы долгим)?
Изящный костыль: Стопка слоев (z-index)

Чтобы обойти ограничение одноразового чекбокса, энтузиасты используют «трюк с колодой карт»:
С помощью шаблонизатора (Pug, PHP, или скрипта на этапе сборки) генерируется, например, 1000 чекбоксов и 1000 кнопок (label) к ним.

С помощью CSS-позиционирования (position: absolute) все 1000 кнопок (label) складываются в одну идеальную стопку друг на друга. Пользователь видит только самую верхнюю кнопку (например, кнопку №1).
Когда пользователь кликает, он нажимает на верхнюю кнопку. Связанный с ней чекбокс №1 переходит в статус :checked (+1 к счетчику).

Добавляется хитрое CSS-правило: как только чекбокс нажат, его label должен исчезнуть (display: none или сдвиг за экран).

Верхняя кнопка исчезает, и под курсором моментально оказывается кнопка №2. При следующем клике нажмется она.

Визуально для пользователя это выглядит как одна и та же кнопка, по которой он кликает раз за разом. А технически — он просто пробивает путь сквозь стопку из 1000 одноразовых кнопок, каждая из которых добавляет +1 к общему CSS-счетчику.
