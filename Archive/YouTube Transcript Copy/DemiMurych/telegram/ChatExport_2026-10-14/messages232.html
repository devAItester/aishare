К вопросу о важности выбора имён идентификаторов.

Браузерный JS. Я написал глобальный обработчик ошибок:

function onerror(msg, url, line, col, error) {
// send data to server to monitor JS errors
}

window.onerror = onerror;


И час ковырялся почему он то не определён, то не срабатывает.
Узнал в процессе, что если script src с другого хоста, то по CORS-безопасности window.onerror не срабатывает, т.к. в инфе об ошибке могут быть чувствительные данные. Но у меня с одного хоста js грузится. Думал-думал и вдруг осенило: onerror уже есть в window, я его переопределяю, и теряется часть функционала! Переименовал в handleError и всё заработало.

Надеюсь, окажется полезно/интересно

Використання вбудованого об'єкта Reflect замість методів конструктора Object є кращим не лише через передбачуваність результатів, а й через низку архітектурних та функціональних переваг, визначених у специфікації ECMAScript.
Ось основні причини, чому Reflect вважається більш досконалим інструментом для метапрограмування:
1. Повернення логічних значень замість помилок
Більшість методів Object (наприклад, Object.defineProperty) у разі невдачі (якщо об'єкт запечатаний або властивість не налаштовується) викидають виключення TypeError.
- Методи Reflect (як-от Reflect.defineProperty або Reflect.preventExtensions) спроектовані так, щоб повертати true у разі успіху та false у разі невдачі.
- Це дозволяє писати чистіший код для перевірки успішності операцій без використання блоків try-catch.
2. Пряма відповідність внутрішнім методам (Internal Methods)
Специфікація визначає набір основних внутрішніх методів (Essential Internal Methods), таких як [[Get]], [[Set]], [[OwnPropertyKeys]].
- Кожен метод Reflect має ідентичну сигнатуру та назву до відповідного внутрішнього методу специфікації.
- Це робить Reflect ідеальним для використання всередині Proxy-пасток (traps). Оскільки пастки проксі-об'єкта також відповідають цим внутрішнім методам, Reflect дозволяє легко делегувати операцію цільовому об'єкту, зберігаючи стандартну поведінку.
**3. Повнота результатів (Reflect.ownKeys)**
Метод Reflect.ownKeys(target) є унікальним, оскільки він повервсі власні ключічі** об'єкта: і рядки, і символи, незалежно від їхньої перелічуваності.
- Для порівняння, Object.keys() повертає лперелічувані рядкові ключічі**.
- Щоб отримати той самий результат через Object, довелося б об'єднувати масиви від Object.getOwnPropertyNames() та Object.getOwnPropertySymbols().
**4. Параметр receiver для коректного успадкування**
Методи Reflect.get та Reflect.set приймають необов'язковий аргумент receiver.
- Цей параметр використовується як значення this, якщо властивість, до якої звертаються, є аксесором (getter/setter).
- Це критично важливо для правильної роботи ланцюжка прототипів та Proxy, оскільки дозволяє перенаправляти операції так, щоб this в методах прототипу вказував на об'єкт, з яким безпосередньо взаємодіє користувач, а не на сам пр5. Функціональний стиль для операторіваторів**
