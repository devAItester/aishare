# Тесты синхронизации dotfiles

Цель: проверить несколько вариантов двусторонней синхронизации Git-репозитория с локальной файловой системой до переноса схемы на реальные конфиги.

Каждый вариант изолирован отдельной папкой:

- `01-timer` — только systemd timer; самый простой вариант.
- `02-path-timer` — локальные изменения ловит systemd.path, удалённые — timer.
- `03-realtime` — локальные изменения ловит systemd.path, удалённые изменения проверяются timer; есть рубильник `on/off`.

Тестировать нужно в отдельной копии репозитория, а не в будущих dotfiles.

Исходные требования к эксперименту:

1. локальный файл является обычным файлом Git working tree;
2. рабочий конфиг впоследствии можно будет представить symlink'ом на этот файл;
3. в обычном режиме GitHub не трогается автоматически;
4. realtime включается отдельной командой;
5. при конфликте автоматизация не должна молча перезаписывать локальную работу;
6. никакого `git push --force`.

Для вариантов с автоматическим push используется обычный fast-forward push. Git сам откажется переписать удалённую ветку, если история разошлась. `--force` намеренно не используется.
