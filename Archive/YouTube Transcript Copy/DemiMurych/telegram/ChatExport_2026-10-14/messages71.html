Далее.
В связи с тем, что многие люди которые пытались описывать работу исключений в JS через свой опыт другых языков программирования (например С) они создали у многих НЕВЕРНЫЙ стереотип.

Будто то бы try - catch это некий контейнер обертка, вокруг блока кода, который следит за всем что в нем, в блоке кода, просиходит.

Это дейсвительно может быть так в ДРУГИХ языка но не в языке JS.

В JS ВСЕ statement возвращают не результат, но некоторую структуру, которая называется complition.
В этой структуре, кроме сыылки на сам результат, содержиться еще долполнительноя информация о том, как этот результат был получен.

Например
function doThing() {
  return "result"
}
doThing();

statement return - создаст структуру complition, которая будет содержать ссылку на результат (строка "result") и содержать детали которые интерпретируются как normal complition. (я не буду грузить самими деталями - просто будем говорить что эти детали интерпретируются спецификацие как normal complition)

Теперь что происходит если мы перепишем код вот так
function doThing() {
  return "result"
}

try {
   doThing();
} catch (e) {

}


Согласно спецификации, try это конструкция которая проверяет complition на то, является ли его состояние abrupt. И если да - выполняет блок catch.

Тут следует уточнить еще два момента.
Сам по себе блок {} точно так же как и return генерирует complition результатом своей работы.
Все вызовы внутри спецификации сейчас сопровождаются предикатом - знаком вопроса ? что означает, что если результат вычисления выражение это именно abrupt complition, то завершить выполнение текущего блока когда и вернуть дальше эту же complition.

То есть в примере выше, если бы мы написали так
function doThing() {
  throw "Error";    // <================
  return "result"
}

try {
   doThing();
} catch (e) {

}


То происходит следующее:
throw - это обыкновенный ретурн с той лиш разницей что он генерирует не normal complition а abrupt complition.
То есть происходит завершение работы функции doThing - естественным образом где возвращшается результат "Error" внутри конструкции complition с флагом abrupt

Мы выходим из вызова doThing() внтури try catch. При этом согласно спецификаии, выполнения call expression всегда делаться вот так: ? call expression. То есть если это выражение завершается с abrupt compition, то не выполнять ничего дальше а делать возврат значение по цепочке.

Блок try - {} это statement который работает точно так же как функция. То есть для спецификации каждый блок кода {} по логике возврата результата очень похож на вызов функции. А это означает что из него вернется тот же abrupt complition что вернул doThing

А тут как раз и н ачинает работать try. Он оценивает результат работы своего блока и если там есть логика abrupt - то передает управление блоку кода catch.

Асинхронность это несинхронность имхо. Когда код выполняется последовательно шаг за шагом это синхронность, обусловленная частотой проца. Асинхронность это все что выполняется не синхронно. И в основном асинхронность проявляет себя когда io операции какие то или таймеры. Например, кнопку нажали на приборе, код который синхронно выполнял ся был прерван и сработал isr на клик кнопки. Если ж в джс кликнуть на кнопку на хтмл страничке, то этот клик как бы запланируется в jobs список. И потом обработается. А может не обработается если вы повесили страницу как то раньше обработки клика. Ну и короч асинхронность это понятие относительное. В атмеге ваша асинхронность привязана будет к кварцевему генератору, в браузере эвент лупу. Можно представить что эвент луп эта некая абстракция процессора. Который как пакмен пожирает команды/таски.
