Язык предоставляет возможность HOST среде принять решение, о том, как она HOST среда, будет распаралеливать работу потоков кода.

Какие именно технологии использовать - лежит на плечах HOST среды. Мультипроцессинг, мулттитреадинг, вытесняющая многозадачность и так далее.
Что вполне логично, потому, что не RunTime JavaScript нужно думать и выбирать какую модель распаралеливания работы кода нужно использовать. Так как это зависит как от архиеткуры процессора так и от операционной системы. От которых RunTime JS изолирован.

В тоже время, если бы спецификация не имела описания того, каким образом будут взаимодейтсвовать между собой threads (это термин спецификации не путать с threads в процессоре) организовать выполнение кода в более чем один поток было бы невозможно.

То есть - современная спецификация, предоставляет HOST среде все возможности, для организации API паралельного выполнения блоков кода.

Почему
console.log( new RegExp({}). test('mom'));
true
console.log( new RegExp({}). test('dad'));
false



Это вопрос, по своей сути, подобен вопросу - почему
[1,2,3] + [1,2,3]; // 1,2,31,2,3


С со своей спецификой именно для конструктора RegExp.
Конструктор RegExp на вход принимает два параметра: 1 - pattern 2-flags.
Просмотрев алгоритм работы конструктора мы видим, что он осуществляет особые шаги только в случае, если получает подтверждение тому что pattern - является валидным RegExp-om или переданный обьект имеет проперти symbol @@match

В нашем случае, передается ссылка на стандартный обьект. То есть на структуру которая не является валидным RegExp и тем более не имеет никакого проперти @@match.

Это приводит к тому, что в конце алгоритма инициализации происходит вызов абстрактной операции: RegExpInitialize(O, P, F).
Где:
O - cозданный под регексп обьект
P - pattern (в нашем случае сюда прийдет ссылка на обычный обьект,, который мы передали вместо настоящего patterna)
F - флаги

Смотрим на первые две строки алгоритма RegExpInitialize
1. If pattern is undefined, let P be the empty String.
2. Else, let P be ? ToString(pattern).

Поскольку pattern у нас определен - то выполняется строка 2: а именно применение асбтрактной операции ToString к нашему паттерну.

Так как у нас, pattern - это ссылка на стандартный обьект, то у такого обьекта согласно спецификации определен метод toString который возвращает:
({}).toString(); 
'[object Object]'

На что похоже [object Object]?
правильно - это типичный класс символов в синтаксисе реуглярных выражений.

То есть мы получили на самом деле вот такой код
console.log( new RegExp( /[object Object]/). test('mom'));
console.log( new RegExp( /[object Object]/). test('dad'));

Иными словами мы получили регулярное выражение которое будет осуществлять поиск в строке одного из символов перечисленных в символном классе.
Строка mom содержит символ o - потому true
Строка dad не содержит ни одного символа из нашего класса - потому false.

Можно себя перепроверить - составиив строку
console.log( new RegExp( {} ). test('dad dad'));

и получить true. Потому что пробельный символ есть в нашем символьном классе.

Другим способом себя перепроверить - является переопределение метода toString у нашего Object

new RegExp( 
    { toString: ()=>'murych boh' } 
).test("murych boh");
true;


Как видим никакой магии нет. Если знать как работает JavaScript.
