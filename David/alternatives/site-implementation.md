# Альтернативы реализации сайта

Документ собирает варианты по темам, которые уже отмечены в архиве David. Это не означает, что все варианты обсуждались ранее или что они уже окончательно выбраны. Подтверждённые статусы находятся в [../decisions.md](../decisions.md) и [../changes.md](../changes.md).

## 1. Компоновка header и навигации

**Подтверждённый факт:** в сохранённом оригинальном CSS у `header` используется `float: left`, а навигация находится в обычном потоке. В тестовой копии применялся CSS Grid; он был отмечен как временный обход сдвига страницы.

| Подход | Плюсы | Минусы / риски | Статус |
|---|---|---|---|
| Воспроизвести исходные `float` и normal flow | Ближе к оригинальному CSS; меньше архитектурных отличий | Нужно проверить сдвиг при загрузке логотипа и взаимодействие с ширинами | Предпочтительный кандидат для проверки, не считать уже выполненным |
| Оставить CSS Grid | Явная сеточная модель и контроль размещения | Отличается от оригинала; может маскировать исходную причину сдвига | Временное решение в истории копии |
| Использовать Flexbox | Простая модель для горизонтального ряда элементов | Также меняет модель компоновки относительно оригинала | Альтернатива, отдельной проверки не было |

## 2. Поведение подвала на коротких и длинных страницах

**Текущее решение:** подвал должен оставаться в потоке после длинного содержимого, а на коротких страницах прижиматься к низу окна, не перекрывая текст.

| Подход | Плюсы | Минусы / риски | Статус |
|---|---|---|---|
| Обычный поток без дополнительной компоновки | Максимально прост; соответствует естественному потоку документа | На коротких страницах подвал может оказаться посреди окна | Поведение оригинала, но не выбранное поведение копии |
| Sticky footer через flex/grid-каркас страницы | Прижимает подвал вниз только при коротком содержимом; длинный текст отодвигает его | Нужна проверка реального DOM-каркаса и размеров viewport | Согласованное поведение копии |
| `position: fixed` | Всегда держит подвал у края окна | Может перекрывать текст и ссылки; не подходит как универсальное решение | Не использовать для требуемого поведения |

## 3. Логотип: PNG или SVG, явные размеры или intrinsic sizing

**Подтверждённые факты:** оригинал использует PNG; в копии использовался SVG. Явные размеры логотипа добавлены в копии, чтобы заранее резервировать место и избежать сдвига страницы при загрузке.

| Подход | Плюсы | Минусы / риски | Статус |
|---|---|---|---|
| Оригинальный PNG | Совпадает с исходным ресурсом; минимизирует различия | Растровое масштабирование может быть менее чётким при других размерах | Отличие формата зафиксировано; пока не считается текущей проблемой |
| SVG | Масштабируется без пикселизации; может быть компактным | Нужно сверить геометрию, viewBox, цвета и соответствие оригиналу | Текущий вариант копии; оставить до отдельного решения |
| Размеры изображения заданы явно в HTML/CSS | Браузер резервирует место до загрузки; уменьшает layout shift | Нужны корректные пропорции; произвольные размеры могут исказить изображение | Сохранить и проверить |
| Только intrinsic sizing без заранее заданных размеров | Меньше дублирования размеров в разметке | Если размеры не известны заранее, загрузка может изменить геометрию страницы | Оригинальная особенность; не копировать автоматически, если критерий — отсутствие сдвига |

Не считать значение `200×42` универсальным стандартом: размеры должны вытекать из самого ресурса и желаемого отображения.

## 4. Генерация страниц и архитектура источника данных

**Подтверждённый факт об Oscean:** это статический сайт; оригинальный проект использует Uxntal и генерирует HTML из текстовых данных/структур. Корневой `index.html` содержит перенаправление на сгенерированную страницу с учётом URL hash и fallback на `site/home.html`. Наша копия рассматривает Jekyll.

| Подход | Плюсы | Минусы / риски | Статус |
|---|---|---|---|
| Сохранить оригинальный движок Oscean/Uxn | Наиболее близко к архитектуре первоисточника | Высокая цена адаптации для изменения содержания и стилей; другой стек и модель данных | Оригинальная архитектура, не текущая реализация копии |
| Jekyll с Markdown, Liquid и каталогами | Использует знакомый статический генератор; поддерживает шаблоны и GitHub Pages | Часть структуры и навигации приходится моделировать средствами Jekyll | Текущая целевая модель копии |
| Собственный минимальный генератор | Можно точно контролировать структуру, URL и выходной HTML | Нужно самостоятельно поддерживать парсинг, ссылки, проверки и сборку | Идея для отдельного исследования, не принятое решение |

## 5. Источник порядка и структуры навигации

У оригинала порядок страниц связан с lexicon/структурой терминов. Для Jekyll-копии принято локальное исключение через `_menu`, при алфавитной сортировке по умолчанию. Подробное сравнение — [menu-order.md](menu-order.md).

Это осознанное архитектурное отличие, а не утверждение, что у оригинала существует аналогичный файл.

## 6. URL и расширения страниц

Целевой ориентир, записанный в проектном контексте: публичные страницы должны иметь URL с `.html`, за исключением корневой страницы. При выборе реализации нужно сравнить:

| Подход | Плюсы | Минусы / риски |
|---|---|---|
| Настроить permalink-шаблон генератора | Правило единообразно и централизованно | Нужно проверить корневую страницу, вложенные каталоги, относительные ссылки и `baseurl` |
| Явно задавать permalink каждой странице | Точный контроль отдельных исключений | Метаданные дублируются; легко забыть страницу или допустить несогласованность |
| Менять имена файлов ради нужного URL | Может быть просто для маленького сайта | Связывает URL с исходным именем; массовые переименования ломают ссылки |

Не менять URL без проверки существующих ссылок и опубликованного сайта. Конкретный статус настройки permalink нужно проверять в активной копии.

## 7. CSS: полное воспроизведение или точечные правки

| Подход | Плюсы | Минусы / риски | Оценка |
|---|---|---|---|
| Сначала переносить полный актуальный CSS и ресурсы, затем сравнивать поведение | Снижает риск пропустить незаметные правила; проще делать diff | Может переносить и особенности, которые позже окажутся ненужными | Предпочтительный процесс копирования |
| Переписывать CSS по визуальному впечатлению | Можно быстро убрать очевидные проблемы | Легко потерять глобальные правила, наследование, состояния ссылок и поведение фона | Не использовать как единственный процесс |
| Сразу модернизировать компоновку и CSS | Может упростить код | Смешивает копирование оригинала с редизайном; сложнее установить причины различий | Только как отдельная, явно согласованная задача |

В [research/findings.md](../research/findings.md) зафиксировано, что пропуск halftone возник из-за отсутствия полного diff CSS как обязательного этапа. При копировании нужно сверять все селекторы, декларации, media queries, ресурсы и пути.

## 8. Метаданные и дополнительные элементы head

В текущем реестре отмечено отличие: в нашей копии добавлен `meta name="color-scheme" content="light dark"`, которого не было в проверенном исходном шаблоне оригинала.

| Подход | Плюсы | Минусы / риски | Статус |
|---|---|---|---|
| Сохранять только подтверждённые метаданные оригинала | Меньше необоснованных отличий | Может не учитывать требования новой платформы | Базовый вариант для точной реплики |
| Добавлять платформенные метаданные по необходимости | Может улучшить интеграцию с браузерами | Влияние может менять внешний вид и должно быть доказано | `color-scheme` — открытый вопрос; проверить влияние |
| Добавлять метаданные «на всякий случай» | Быстро | Усложняет поиск причин визуальных и поведенческих отличий | Не рекомендуется |

## 9. Организация локального архива и проверок

| Подход | Плюсы | Минусы / риски | Оценка |
|---|---|---|---|
| Хранить первоисточники, исследования, решения и различия раздельно | Можно отличить факт от интерпретации и решения | Нужны ссылки между файлами и обновление статусов | Текущая структура архива |
| Смешивать цитаты, выводы и решения в одной заметке | Быстро начать | Источник утверждения и статус решения становятся неясными | Не использовать как основную структуру |
| Сохранять только ссылки на upstream | Архив меньше | Повторный анализ требует сети; исходники могут измениться | Не соответствует цели автономного архива |
