Да — в результате цепочки обработки, но нет — при прямом вызове самого метода.

1. Прямой вызов Promise.reject(r) — всегда rejected
Согласно спецификации ECMAScript (раздел Promise.reject):

Метод получает внутренние возможности промиса (NewPromiseCapability(C)).
Вызывает встроенную функцию promiseCapability.[[Reject]] со значением r.
Возвращает созданный промис promiseCapability.[[Promise]].

В отличие от Promise.resolve(), функция [[Reject]] не разворачивает переданный объект (thenable или другой промис). Даже если передать в Promise.reject(Promise.resolve('ok')) уже успешно выполненный промис, результатом будет отклоненный (rejected) промис, причиной (reason) которого станет объект исходного промиса.
JavaScript
const p = Promise.reject(Promise.resolve('ok'));
// Состояние p: rejected, причина: Promise { <fulfilled>: 'ok' }


2. Получение fulfilled промиса в цепочке через .catch() / .then()
Согласно спецификации (раздел PromiseReactionJob):
Когда отклоненный промис обрабатывается функцией onRejected в .then(null, onRejected) или .catch(onRejected), движок вызывает этот обработчик.
Если обработчик завершается нормально (через return value без генерации ошибки throw), внутренний алгоритм вызывает Resolve(resultCapability, handlerResult).
В результате возвращается новый промис в состоянии fulfilled.
JavaScript
Promise.reject('error')
  .catch(err => 'handled') // возвращает resolved промис со значением 'handled'
  .then(val => console.log(val)); // 'handled'


3. Использование в комбинаторах
Promise.allSettled([Promise.reject('err')]) — всегда возвращает промис в состоянии fulfilled с массивом описания статусов [{ status: 'rejected', reason: 'err' }].
Promise.any([Promise.reject('err'), Promise.resolve('ok')]) — игнорирует отклоненный промис и переходит в состояние fulfilled при первом успешном значении.
