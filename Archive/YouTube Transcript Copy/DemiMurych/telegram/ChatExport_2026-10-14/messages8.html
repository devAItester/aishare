1. Как известно, v8 оптимизирует функции которые постоянно получали одинаковый тип данных в кач-ве аргумента. И деоптимизирует функции, которые получают в качестве аргументов различные типы.
Это чепуха.
V8 глубоко пофигу как вызывается функция, при условии, если функция вызывается с ОДИНАКОВЫМ колличеством параметров.

V8 пофигу на то какой там тип. Потому, что все идентификаторы - это ссылки. Там ничего оптимизации помешать не может.

Вся тагомотина начинается именно ТАМ, где эти идентификаторы используются.
И чтобы показать наглядно то, о чем я говорю я приведу пример кода, когда передача РАЗНЫХ типов не приведет к деоптимизации функции, которая была оптимизирована:
(код специально написан в максимально доступной форме)

var doThing = (
    ( theThing ) => {
        if ( Array.isArray( theThing ) ) {
            return theThing[0];
        } else {
            return theThing + 10;
        }
    }
);

var theThingPlusTen = doThing( 5 );
var theThingIndexZero = doThing( [1,2,3] );


Суть примера выше показать главное, что никаких деоптимизаций из за переданого иного типа - НЕ БУДЕТ.
более того, если по каким то причинам, функция 
doThing
будет оптимизирована, то при передачи в нее либо числа либо массива ровно точно так же не приведет к деоптимизации.


ОПТИМИЗИРУЕТСЯ код, который выполняется с теми ссылками КОТОРЫЕ передаются в параметры.
и этот код, можно самостоятельно образом как показано в примере ( когда мы сами персонально отслеживаем тип данных и логику выполенния в зависимости от типа) организовать так, что если его V8 оптимизирует то деоптимизации не будет - ПОТОМУ ЧТО МЫ САМИ сделали все проверки и все необходимое завернули в разные ветки логики.


То есть, изначальный тезис о том, что в функцию нужно передавать одинаковые типы - ЛОЖНЫЙ.
Важно только одинаковое колличество передаваемых параметров. Если у функции один параметр - то всегда и передавать один параметр. Даже если в какойто ситуации этого параметра - НЕТ. ВСегда передавать один параметр. Например вместо него undefined.

Правильный тезис заключается в том, что работа внутри функции с этими идентификаторами, должна быть такой, которая бы не менялась в зависимости от ТИПА того что было передано.

Оптимизация - это процесс создания машинного кода, который, опираясь на тот тип данных ради коотрого его создали, выбирает наиболее оптимальную форму чтобы выполнить задачу.
Например - код в функции из примера к переданному параметру добавляет 10.
Тогда оптимизированный код изначально будет исходить из того, что это всегда будет целое число к которому добавляется целое 10.

А в той части функции где мы оперируем массивом - будет другой оптимизированный код, который будет иметь сразу прописанный доступ к ячейке памяти массива, которое и будет результатом работы функции. И пофиг что там дежит.
