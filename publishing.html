05 / Verification

A successful commit is not a successful site.

The source tree, generated HTML, and deployed website are three separate things. Verify each layer before calling a change complete.

Before publication

  1. Check the changed files and inspect the diff.
  2. Confirm that all pages reference the same external stylesheet.
  3. Check internal links, filenames, capitalization, and expected .html URLs.
  4. Confirm there are no missing assets or accidental copies of CSS in page heads.
  5. Inspect a short page, a long page, and a page with a large heading.

After publication

  1. Open the public URL, not only the repository preview.
  2. Request the home page and stylesheet directly; check status and content type.
  3. Follow representative internal links and refresh a nested page directly.
  4. Inspect layout at a narrow viewport and a wide viewport.
  5. Compare the result against the reference and record remaining differences.

Performance claims require measurement

A separate stylesheet enables caching, but that does not by itself prove a faster first render. If performance matters, compare cold and warm cache behaviour and record the conditions. Do not attribute CSS parsing or layout work to V8: V8 is the JavaScript engine, while style and layout are browser rendering work.

Report status precisely

Use separate states: source changed, build passed, deployment observed, visual comparison completed. If a browser check was not possible, say so. See the decision register for unresolved items and source policy for evidence standards.
