Ответ
спецификация языка JS не диктует никаких правил работы с памятью.

Єти правила выбирает сама для себя хост среда или агент интегрированный в хост, который кроме реализации спецификации, может предоставить и необходимое апи для работы с памятью.

Предоставить как для самого js кода, так и для хост среды.


Как следствие - создание хоста/агента который только наполнаяет память нужными данными и не заботититься о том, что неиспользуемые в текущий момент данные из памяти не удаляются - нормальное поведение с точки зрения спецификации.


И поведение - когда GC не сущестсует,  реально используется в создании как высоко производительных приложений на js, так и в создании кода на js для встаиваемых устройств с слабыми вычислительными ресурсами.

Что дает бурст в производительности но и накладывает значимые требования для программиста создающего js код, как того, который понимает к чему приводит та или иная конструкция.

const mergeData = (parsedData, locale = 'unknown', initialResolution = {}) => {
  const result = Object.entries(parsedData).reduce((acc, [category, details]) => {

class MergingData {
  constructor(parseData) {
    this.browser = this._formatData(parseData.browser);
    this.os = this._formatData(parseData.os);
    this.device = this._formatDeviceData(parseData.device);
    this.cpu = parseData.cpu?.architecture ?? UNKNOWN;
    this.locale = UNKNOWN;
    this.initialResolution = UNKNOWN;
  }

  _formatData({ name, version }) {
    return (name || version)
      ? `${name ?? UNKNOWN}, ${version ?? UNKNOWN}`
      : UNKNOWN;
  }

  _formatDeviceData({ model, type, vendor }) {
    return (model || type || vendor) 
      ? `${model ?? UNKNOWN}, ${type ?? UNKNOWN}, ${vendor ?? UNKNOWN}` 
      : UNKNOWN;
  }

  setLocale(locale) {
    if (locale) this.locale = locale;
    return this;
  }

  setResolution({ w, h }) {
    if (w && h) this.initialResolution = `${w}x${h}`;
    return this;
  }
}
