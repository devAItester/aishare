почему if/else и switch плохие абстракци и их следует заменить на actor model?
начнем со switch, который по сути является расширением if/else и с того, что ситуации, где такая абстракция может пригодиться при правильной архитектуре просто не существует. если у вас есть значение, и значения, которые следует сопоставить с данным следует запихнуть их в однородное множество ( например, Map или Array ) и сопоставить им функции, которые выполнятся при совпадении. это даёт больше расширяемости т.к. функции в отличие от блоков кода могут быть переиспользованы, а также это поведение может быть легко перекомбинировано программным путем т.к. мы по сути определили его в данные .
теперь на счёт if. опять же ради переиспользования кода мы хотим использовать функции вместо блоков кода, и даже вместо условий. а теперь посмотрим, как это записывается в моем яп с использованием actor model:
условный переход 
docheck
cond1 = fn1
cond2 = fn2

безусловный переход
fn1
fn2

т.е. безусловный переход легко дополняется до условного. в отличие от типичных яп, где используется return и if. нам либо придется запихивать в объект результат ( возвращаемый из return) какой-то Стейт результата который будет определять поведение, что очевидно плохой подход, либо использовать принципы самого actor model и делать обратные вызовы( на разные кейсы вызывать методы с разными именами) . но зачем тогда вообще return и if? если все будет выражено в обратных вызовах нам уже не потребуется ничего проверять, а просто надо будет определять реакции на определенные сообщения, как и описывается в actor model

итого: switch заменяется на однородное множество т.к. по сути не имеет поведения, а имеет только данные
if + return заменяются на actor model т.к. имеет плохие возможности для расширения от безусловного до условного перехода

            "Negative": this.handleNegative,
            "ZeroToHundred": this.handleZeroToHundred,

        };

        this.messageTypes = {
            Negative: (value) => value < 0,
            ZeroToHundred: (value) => value >= 0 && value < 100,
            AboveHundred: (value) => value >= 100,
        };
    }

    onMessage(msg) {
        const handler = this.handlers[msg];
        if (handler) {
            handler.call(this);
        }
    }

    handleNegative() {
        console.log("Обработка отрицательного значения");
    }

    handleZeroToHundred() {
        console.log("Обработка значения от 0 до 100");
    }

    handleAboveHundred() {
        console.log("Обработка значения больше 100");
    }

    getMessageType(value) {
        for (const [key, condition] of Object.entries(this.messageTypes)) {
            if (condition(value)) {
                return key;
            }
        }
        return null; // Если ни одно условие не выполнено
    }

    send(value) {
        const msg = this.getMessageType(value);
        if (msg) {
            this.onMessage(msg);
        }
    }
}
