# Применение принципов к сайту «Полевые заметки»

## Принятая структура

~~~text
.
├── _data/
│   └── navigation.yml
├── _layouts/
│   └── default.html
├── assets/
│   └── main.css
├── Archive/
│   └── Timur/
├── index.md
├── project.md
├── architecture.md
├── navigation.md
├── styling.md
├── publishing.md
├── decisions.md
├── sources.md
├── map.md
├── _config.yml
└── README.md
~~~

## Поток сборки

1. Markdown-файлы задают содержание страниц и локальные метаданные.
2. <code>_data/navigation.yml</code> задаёт меню отдельно от контента.
3. <code>_layouts/default.html</code> добавляет общую оболочку и читает меню.
4. <code>assets/main.css</code> задаёт внешний вид без дублирования CSS.
5. Jekyll преобразует исходники в статические HTML-файлы.
6. <code>Archive/</code> исключён из публикации и не участвует в сборке.

## Границы зависимостей

- Страница использует общий layout как способ представления, но её основной текст остаётся самостоятельным Markdown.
- Layout зависит от схемы навигационных данных: у каждого пункта есть <code>title</code> и <code>url</code>.
- CSS подключён в одном месте — в layout.
- Архив не является зависимостью ни одного из этих слоёв.
- Ссылки на темы задаются в содержимом; позднее их можно анализировать автоматически, не перенося знания в отдельную дублирующую базу.

## Проверки, которые должны появиться

- Все URL из навигации ведут на существующие страницы.
- Все внутренние ссылки ведут на выходные HTML-адреса.
- Каждая страница использует ожидаемый layout и общий CSS.
- Сборка не копирует Archive в результат.
- Изменение пункта меню требует изменения только файла данных.
- Изменение общей оболочки требует изменения только layout.

## Статус

Это архитектурное решение для текущего небольшого сайта, а не универсальная схема для всех приложений. Структура должна усложняться только тогда, когда появится проверяемая потребность.
