# Полный сбор данных одного видео через yt-dlp

## Цель

Проверить на одном видео, какие данные можно получить через установленную версию `yt-dlp`, не скачивая сам видеофайл. Тестовый ролик: https://www.youtube.com/watch?v=DjuK8h7-ep8.

На этом этапе ничего не отбрасывать и не преобразовывать с потерей данных. Сначала сохраняются исходные результаты и логи; отбор полей можно будет сделать позднее отдельным производным этапом.

## 1. Создать отдельный каталог теста

Выполнить в терминале Arch Linux:

    mkdir -p ~/youtube/AsForJS/full-data/DjuK8h7-ep8
    cd ~/youtube/AsForJS/full-data/DjuK8h7-ep8
    yt-dlp --version > yt-dlp-version.txt
    cat yt-dlp-version.txt

Каталог теста отделён от ранее собранных данных вкладок канала и не перезаписывает их.

## 2. Сохранить полный JSON, субтитры и миниатюры

Выполнить блок целиком:

    url='https://www.youtube.com/watch?v=DjuK8h7-ep8'

    yt-dlp \
      --skip-download \
      --write-info-json \
      --no-clean-info-json \
      --write-subs \
      --write-auto-subs \
      --sub-langs all \
      --write-all-thumbnails \
      --output '%(id)s.%(ext)s' \
      "$url" \
      > collect.log 2>&1
    printf 'yt-dlp exit status: %s\n' "$?" | tee collect-status.txt

Команда не должна скачивать видео- или аудиопоток. Она пытается сохранить:

- полный файл метаданных `DjuK8h7-ep8.info.json`;
- доступные обычные и автоматически сгенерированные субтитры всех языков в форматах, которые выберет yt-dlp;
- доступные варианты миниатюр;
- диагностический вывод в `collect.log` и код завершения в `collect-status.txt`.

`--no-clean-info-json` нужен, чтобы не просить yt-dlp удалять из info JSON поля, которые обычно считаются избыточными для обычного использования. Наличие файла ещё не доказывает, что все дополнительные ресурсы доступны: результаты необходимо проверить отдельно.

## 3. Отдельно сохранить список доступных форматов

    yt-dlp \
      --list-formats \
      'https://www.youtube.com/watch?v=DjuK8h7-ep8' \
      > formats.txt 2>&1
    printf 'yt-dlp exit status: %s\n' "$?" | tee formats-status.txt

Это текстовый перечень форматов, доступных на момент запроса. Он полезен для последующего выбора качества и аудио/видеокомбинации, но сам по себе не скачивает медиаданные.

## 4. Отдельно сохранить список субтитров

    yt-dlp \
      --list-subs \
      'https://www.youtube.com/watch?v=DjuK8h7-ep8' \
      > subtitles-available.txt 2>&1
    printf 'yt-dlp exit status: %s\n' "$?" | tee subtitles-status.txt

Этот отчёт позволяет сопоставить заявленные YouTube языки и типы субтитров с реально созданными файлами. Не считать отсутствие subtitle-файлов ошибкой без проверки отчёта: у ролика может не быть доступных субтитров либо доступ может быть ограничен.

## 5. Проверить результаты

    cd ~/youtube/AsForJS/full-data/DjuK8h7-ep8

    printf '\n=== Файлы и размеры ===\n'
    find . -maxdepth 1 -type f -printf '%f\t%s bytes\n' | sort

    printf '\n=== JSON: проверка синтаксиса ===\n'
    jq -e 'type == "object"' DjuK8h7-ep8.info.json >/dev/null \
      && echo 'info JSON: valid' \
      || echo 'info JSON: missing or invalid'

    printf '\n=== Поля полного JSON ===\n'
    jq -r 'keys[]' DjuK8h7-ep8.info.json | sort

    printf '\n=== Статусы и сообщения сборщика ===\n'
    cat collect-status.txt formats-status.txt subtitles-status.txt
    cat collect.log

Проверить наличие файлов вручную и изучить все логи. Сохранить исходный JSON целиком; не заменять его списком ключей или сокращённым JSON. Если сборщик завершился с ошибкой, выяснить причину и повторить нужный шаг после исправления, не удаляя предыдущие логи.

## 6. Комментарии — отдельный эксперимент

Комментарии не включены в первоначальный блок: их объём и доступность могут существенно отличаться от ролика к ролику. После проверки базового набора отдельно испытать опцию `--write-comments` на этом же видео, сохранить результат и лог, измерить размер и сравнить полученные поля. Не запускать массовый сбор комментариев, пока не оценены объём и поведение на одном ролике.

## 7. Что зафиксировать после теста

После запуска дополнить документацию фактическими результатами:

- версия yt-dlp;
- код завершения каждого шага;
- фактические имена и размеры созданных файлов;
- число доступных обычных и автоматических субтитров и какие файлы действительно сохранились;
- число вариантов миниатюр, которые удалось получить;
- дополнительные поля полного JSON по сравнению с плоской записью из `tree-data.json`;
- ошибки или ограничения, найденные в логах;
- результат отдельного теста комментариев.

Только после проверки одного видео проектировать массовый сбор. Не удалять исходные поля и не делать предположений о ненужных данных до того, как возможности инструмента будут инвентаризированы.
