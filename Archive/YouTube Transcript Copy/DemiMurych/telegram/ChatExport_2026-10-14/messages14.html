Ну, смотри. Можем говорить со стороны CS, со стороны спеки, которая в своих заключениях может на него опираться или не опираться, можем говорить со стороны рантайма. Если говорить про CS и взять какое-нибудь из рандомных определений вида: "Primitive data types are those that are not defined in terms of other data types.", то можно сделать вывод, что в js все non-Object это примитивные типы, так как представляют собой совокупность примитивных значений.
Если говорить о спецификации:
1. Строковое значение (String value) это примитивное значение из конечного числа последовательных 16-bit unsigned integer.
2. Тип String (String type) это совокупность всех примитивных строковых значений.
3. Строковый объект (new String()) это член типа Object (!), созданный при помощи встроенного конструктора String (то есть, объект, чьим прототипом является String.prototype), во внутреннем слоте которого находится String value.
Грубо говоря, тип String является "примитивным" типом, представляющий собой совокупность сырых данных, не имеющий внутренней структуры (по CS). А методы к этому "примитивному" типу предоставляются при помощи создания объекта класса Object, прототипом которого будет является объект с названием String.prototype. То есть, String value и new String относятся к разным типам данных, что может показаться не интуитивным.

С третьей стороны существуют движки, которые могут проводить любые манипуляции с этими типами, сохраняя лишь внешнее поведение, имея совершенно другую внутреннюю структуру (так, по-настоящему примитивными в v8 являются лишь SMI, а остальные типы представлены отдельными классами с несколькими разными классами для строк https://github.com/danbev/learning-v8/blob/master/notes/string.md)

А главный вопрос, которым стоило задаться перед началом натягивания типов в JS на примитивную-непримитивную сову: "А какую нам вообще это может дать полезную информацию? Что должно изменится в нашем мировосприятии оттого, можно ли назвать с чьей-то точки зрения типы в JS примитивными или нельзя?".
