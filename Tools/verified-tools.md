# Проверенные инструменты

Состояние на 2026-10-09. Статус относится только к указанной операции в текущем окружении, а не ко всем возможностям инструмента.

## GitHub: чтение репозитория

### `mcp__GitHub__fetch`

**Статус: проверено.** Через GitHub connector получен список файлов репозитория `devAItester/aishare` запросом к GitHub REST API `https://api.github.com/repos/devAItester/aishare/contents/`. В предыдущей проверке также успешно читались файлы и каталог репозитория `devAItester/d01-jk`.

Подходит для чтения доступных текстовых ресурсов GitHub: содержимого репозитория, каталогов, файлов и Raw URL. Это не браузерный рендеринг страницы.

Документация: [GitHub REST API — Repository contents](https://docs.github.com/en/rest/repos/contents).

### `mcp__GitHub__fetch_file`

**Статус: проверено.** Прочитаны `README.md`, `rules.md`, `Index/index.md` и `Rules/index.md` в `devAItester/aishare`.

Подходит для чтения конкретного файла по пути и получения его текущего содержимого и blob SHA. SHA нужен, чтобы безопасно обновлять существующий файл через GitHub connector.

Ограничение: успешное чтение одного репозитория или файла не доказывает доступ ко всем репозиториям и ресурсам.

### `mcp__GitHub__create_file` и `mcp__GitHub__update_file`

**Статус: доступны в инструментарии; отдельная запись в момент составления этого документа ещё не подтверждена.** Эти операции предназначены соответственно для создания нового файла и обновления существующего файла через GitHub Contents API. Перед обновлением нужно прочитать актуальный файл и использовать его текущий blob SHA.

Документация: [GitHub REST API — Create or update file contents](https://docs.github.com/en/rest/repos/contents).

## Внешние страницы: чтение текста

### `web.run` → `open`

**Статус: проверено с ограничениями.** Открытие `https://wiki.xxiivv.com/` вернуло текст страницы. Открытие опубликованных страниц `https://devaitester.github.io/d01-jk/`, `https://devaitester.github.io/d00-jk` и `https://devaitester.github.io/flatfiletxtdb` сообщило, что URL недоступен через эту операцию.

Это означает только, что конкретная операция `open` не смогла получить эти URL в данном запуске. Это не доказывает, что сайты выключены или что файлы отсутствуют.

`open` не подтверждает полноценный визуальный рендеринг, точную геометрию страницы, состояние интерактивного меню, загрузку всех изображений и шрифтов или поведение CSS.

### `web.run` → `fast` и `web.run` → `slow`

**Статус: проверено как поиск.** Эти операции выполняют веб-поиск. Они полезны для поиска документации и публичных сведений, но не заменяют получение точного HTML/CSS конкретной страницы и визуальный браузерный тест.

## Браузер и визуальные тесты

### Firefox DevTools — Inspector и Network

**Статус: доступно локально пользователю; управление браузером из этой сессии не подтверждено.** В Firefox можно осмотреть DOM и применённые стили во вкладке Inspector, а сетевые запросы и ошибки загрузки — во вкладке Network.

Документация Mozilla: [What are browser developer tools?](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Tools_and_setup/What_are_browser_developer_tools).

### Playwright

**Статус: не проверено и не подтверждено как установленный инструмент в текущей сессии.** Playwright подходит для автоматизации браузера и снятия скриншотов, но наличие доступного исполняемого окружения здесь не установлено.

Документация: [Playwright screenshots](https://playwright.dev/docs/screenshots).

## Что пока не подтверждено

- Полноценный браузерный рендеринг и получение скриншотов сайта из текущей AI-сессии.
- Автоматическая проверка визуального сходства эталона и копии при одинаковом viewport.
- Проверка фактической загрузки каждого изображения, шрифта и CSS в браузере.
- Успешная запись файлов в репозиторий именно через `mcp__GitHub__create_file` / `mcp__GitHub__update_file` в рамках этой проверки.
