ВСЕ ПРИМЕРЫ НИЖЕ, ЭТО НЕ JS КОД,
НО КОД СПЕЦИФИКАЦИИ ECMA


Первое с чего нужно начать - это четко понять, что любая реализация языка JS, ВСТРАИВАЕТСЯ кудато.
Это куда-то называется HOST средой.
HOST среда может делать все что ей вздумается.

Далее:
Есть спецификация ECMA в которой СТРОГО закреплено, что все обмены данными в рамках спецификации это reference like поведение, что означает:
Имплементация языка, если она реализует правила спецификации, ОБЯЗАНА сделать так, что любые данные, которые в алгоритмах спецификации связываются между собой через let ОБЯЗАНЫ ссылаться на одно и тоже.
При этом сказано, что возможно копирование данных, если это явным образом указано (написано be a copy).

ВАЖНО
Изменение любого из таких идентификаторов - автоматически обязано приводить к изменению любого из тех же кто был с ними связан.
let var1 = 1.
let var2 = var1.
set var1 = 2.

var2 в пределах алгоритмов спецификации теперь тоже связано с 2.


В спецификации есть только 9 особых случаев когда прямо требуется копирование данных.
3 из которых касаются описания поведения запуска функционального обьекта, где копируются не сами данные, а контекст, который описывает особенности исполнения функции. (не путать слово контекст с this).
То есть это случай коотрый не волнует JS программиста в случае когда он работает с данными, тут особенности реализации.

3 случая касаются описания поведения методов JS для Set, где это касается манипулирования ключами обьекта,
что опять же не копирует то, что программист JS привык называть данными.

2 случая касаются Atomics API, для взаимодейтсвия между нескольким независиммы агентами и решеним проблем с коллизиями.

1 случай для описания особенностей поведения Exotic Object Array в случае изменения property length.


Промежуточное ИГОГО:
Спецификация по умолчанию устроена так, что любые манипуляции с данными в рамках алгоритмов спецификации, должны строго следовать правилу - одно и тоже данное имеет одну и туже ссылку на него вне зависимости от используемого идентификатора.

То есть мы знаем, что везеде в спецификации, где мы видим слово Let (непутать с JS let) то это означает, что идентификатор связанный с этим данным долэжен быть согласно спецификации связан точно так же как и любой другой let в спецификации, если прямо не указано BE A COPY.
Let newLen be 1;
Let newLen2 be newLen;
Let newLenDesc be a copy of newLen.

идентификаторы newLen и newLen2 - обязаны указывать на одну и туже структуру.
И только newLenDesc приведет к копированию данных.



Далее про HOST:
Хост среда, как и потенцильно что-то из частей спецификации МОЖЕТ создавать копии данных.
Например в V8, есть особый внутренний тип строки, который так и обозначен EXTERNAL и эта строка, может иметь совсем иную ссылку чем ТАКАЯ ЖЕ РАНЕЕ СОЗДАННАЯ строка в рамках JS кода.


Вместо ИГОГО
Когда код, работает строго в пределах правил спецификации, и не касается ситуаций с Atomics API, то согласно спецификации он ОБЯЗАН устроен быть таким образом, чтобы внутренняя реализация (например V8) имела одну и туже ссылку на данные которые вы называете примитивными.

то есть число 1, если они используется в программе, согласно спецификации, обязано иметь свое описание где-то в куче, и любое использование числа 1 в любом месте программы, должно иметь одну единсвенную ссылку на это описание.

КАК РЕАЛИЗОВАНО это описание - спецификация не регламентирует. Он просто говорит что так должно быть. Конкретная реализация (например V8) вольна выбирать сама как ей удобно. НО правила описание выше должны быть соблюдены.

И есть ряд исключений:
Atomics API - которые могут дублировать данные
Данные которые навязала HOST среда именно так как ей это было надо
Алгоритмы оптимизации движка JS. (например V8 не будет создавать реальное описание числа 1 или ссылаться на него, когда понимает что ему нужно сделать всего лишь простой цикл от 0 до 5)
