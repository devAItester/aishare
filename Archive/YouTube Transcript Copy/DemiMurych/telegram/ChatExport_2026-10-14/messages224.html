Абсолютно проклятая идея — хранить файлы в DNS-кеше. Хотя, вот сейчас уже не кажется такой безумной.

Инженер Бен Кокс (benjojo) сделал DNSFS — файловую систему, которая хранит данные не на диске, а в кешах чужих DNS-резолверов по всему миру.

Логика простая. Резолверы кешируют ответы на время TTL, причём некоторые держат запись до недели. Бен предложил класть туда не доменное имя, а куски своего файла: записал TXT-запись с гигантским TTL — и чужой роутер где-нибудь в Корее стал ячейкой твоего хранилища.

Идейно это наследник PingFS, где данные летали внутри ping-пакетов. Но DNS лучше: есть кеш, один раз отправил — и пакеты гонять не надо, пока запись не протухла.

Чтобы было куда писать, нужны открытые рекурсивные резолверы. По уму их закрывают фаерволом (классический вектор DDoS-амплификации), но кривые дефолтные конфиги домашних роутеров делают своё дело. Бен просканировал почти весь интернет через masscan и собрал около 3,8 млн открытых резолверов. Лидеры: Китай, США, Корея, Россия, Бразилия.

По его замерам около 18% резолверов держат кеш примерно сутки, а суммарный полезный объём — порядка 250 МБ при тройной репликации. Файл режется на куски по 180 байт, раскладывается по резолверам и стирается с компьютера клиента — то есть живёт только в чужих кешах.

Практической пользы ноль, но как памятник инженерному хулиганству и иллюстрация того, сколько открытых резолверов всё ещё торчит наружу, — отлично.

Код: github.com/benjojo/dnsfs
Разбор автора: blog.benjojo.co.uk/post/dns-filesystem-true-cloud-storage-dnsfs

export interface Signal<T> {
  get: () => T;
  set: (n: T) => void;
  sub: (f: () => void) => () => void;
}

export const createSignal = <T,>(initialValue: T): Signal<T> => {
  const subs = new Set<() => void>();
  let v = initialValue;

  return {
    get: () => v,
    set: (n: T) => {
      if (!Object.is(n, v)) {
        v = n;
        [...subs].forEach((f) => f());
      }
    },
    sub: (f: () => void) => {
      subs.add(f);
      return () => { subs.delete(f); };
    }
  };
};
