02 / Structure

Plain files are the source of truth.

The structure should remain legible in a text editor, a terminal, and GitHub. A generator may help publish it, but it must not become the only place where the system makes sense.

Three distinct layers

Source material
Original pages, captured CSS, reference files, and research evidence. Preserve provenance and do not rewrite these as if they were our own conclusions.
Curated knowledge
Short, maintained pages with a clear purpose, explicit links, and a known status. This is the site a person reads.
Published output
Static HTML and CSS that a browser can serve directly. Generated output should be inspectable and should not require client-side JavaScript to reveal the content.

Folder structure is not the whole information architecture

Folders provide a physical address. Links express semantic relationships. A page about CSS may belong under implementation, but it should also link to the reference evidence, the chosen delivery method, and the test procedure. This is why backlinks and related links are part of the content model rather than decoration.

Generator choice

Oscean is not a conventional Jekyll project: its original repository describes a static wiki generated from plain-text data using Uxntal. Jekyll is a possible publishing layer for our copy, not an interchangeable implementation of the original architecture. A custom generator remains an option only if the constraints of the current toolchain justify its maintenance cost.

Practical constraints

  • Prefer stable, human-readable filenames and URLs.
  • Keep the shared stylesheet outside individual HTML documents.
  • Avoid a JavaScript runtime for content that static HTML can express.
  • Make the home page a useful map, not a duplicate dump of every page.
