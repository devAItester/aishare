За допомогою вірусного комп'ютерного хробака Shai-Hulud скомпрометовано 600 NPM-пакетів

Зафіксовано другу атаку на пакети в репозиторії NPM, проведену з використанням модифікації саморозповсюджуваного хробака Shai-Hulud, який підставляє шкідливе ПЗ у залежності. Внаслідок атаки опубліковано шкідливі релізи 605 пакетів, які сумарно мають понад 100 млн завантажень.

Для проведення атаки зловмисники шляхом фішингу перехопили параметри облікового запису супроводжуючого одного з популярних пакетів, що використовується як залежність у великої кількості пакетів.

Скориставшись захопленим обліковим записом, атакувальники опублікували реліз пакета, до якого додали код для активації хробака при встановленні ураженого пакета серед залежностей.

Запущений хробак виконує пошук облікових даних у поточному оточенні, завантажуючи та запускаючи утиліту TruffleHog.

У разі виявлення токена підключення до каталогу NPM хробак автоматично публікує нові шкідливі релізи для пакетів, що розробляються у поточному оточенні. Таким чином по ланцюжку уражається все дерево залежностей. Окрім NPM-токена, хробак зберігає ключі доступу до GitHub та хмарних сервісів AWS, Azure і GCP (Google Cloud Platform), а також змінні оточення та інші конфіденційні дані, які здатен виявити сканер TruffleHog.

Знайдені в системі конфіденційні дані розміщуються у GitHub через створення репозиторіїв з хаотичними іменами (наприклад, "qzx15djl71alh6p80h") та фразою "Sha1-Hulud: The Second Coming" у описі, а також у закодованому вигляді виводяться у логи GitHub Actions. У створеному репозиторії розміщується файл у форматі JSON (наприклад, jsonactionsSecrets.json або contents.json), у якому присутній рядок із закодованою методом base64 інформацією про систему, змінні оточення та захоплені дані. Для передачі інформації назовні з систем безперервної інтеграції на базі GitHub хробак створює обробник GitHub Actions з іменем ".github/workflows/formatter_123456789.yml" та налаштовує runner з іменем SHA1HULUD.

Відмінності від подібної вересневої атаки полягають в іншому методі підстановки шкідливого коду в пакет. У формованих хробаком шкідливих релізах заявляється реалізація підтримки JavaScript-платформи Bun. У файл package.json у секцію "preinstall", що визначає скрипти, які запускаються до початку встановлення, додається команда "node setup_bun.js".

У файлі "setup_bun.js" міститься код для виконання обфусцированого скрипта "bun_environment.js", що містить код хробака. Для подальшого поширення хробак знаходить код пакетів, вносить зміни у файл package.json (збільшує номер версії та включає виклик setup_bun.js), додає файли setup_bun.js і bun_environment.js, перепаковує пакет і виконує команду "npm publish" для розміщення нового релізу.

У Grafana Enterprise знайшли спосіб отримати адміна без реєстрації та СМС

Розробники Grafana Labs вирішили пожвавити корпоративний сектор і випустили попередження про критичну вразливість CVE-2025-41115, яка отримала максимальний рейтинг небезпеки (10 з 10). Проблема стосується виключно платної редакції Grafana Enterprise і дозволяє зловмиснику легко перетворитися на адміністратора, захопивши повний контроль над системою моніторингу та всіма даними.

Якщо в системі увімкнена функція синхронізації користувачів через протокол SCIM (параметри enableSCIM та user_sync_enabled встановлені в true), то механізм зіставлення облікових записів починає поводитися неадекватно. Шкідливий клієнт може передати в поле externalId числове значення, наприклад (1). Система, не довго думаючи, мапить це значення прямо на внутрішній user.uid. А оскільки uid=1 це зазвичай супер-адмін, то Grafana радо пускає гостя з повними правами.

Користувачі безкоштовної Grafana OSS у безпеці. Також у безпеці ті, хто не вмикав експериментальну функцію SCIM provisioning. Але якщо ви щасливий власник ліцензії Enterprise версій 12.0.0–12.2.1 і використовуєте автопровіжнінг користувачів, то у вас проблеми.

Всім власникам self-host настійно рекомендується встановити оновлення до версій 12.3.0, 12.2.1, 12.1.3 або 12.0.6, поки до вас не постукав новий адмін з зовнішнім ID.

No this substitution

The value passed as this to a function in strict mode is not forced into being an object (a.k.a. "boxed"). For a sloppy mode function, this is always an object: either the provided object, if called with an object-valued this; or the boxed value of this, if called with a primitive as this; or the global object, if called with undefined or null as this. (Use call, apply, or bind to specify a particular this.) Not only is automatic boxing a performance cost, but exposing the global object in browsers is a security hazard because the global object provides access to functionality that "secure" JavaScript environments must restrict. Thus for a strict mode function, the specified this is not boxed into an object, and if unspecified, this is undefined instead of globalThis:
