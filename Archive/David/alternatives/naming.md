# Naming: имена файлов, каталогов и URL

Дата исследования: 2026-10-09. Это исследовательская рекомендация для проектирования копии, а не разрешение массово переименовывать текущие файлы.

## 1. Разделять три разных имени

| Что именуем | Пример | Кто на него влияет |
|---|---|---|
| Исходный файл | `path-and-url.md` | Структура проекта, соглашения генератора, удобство редактирования |
| Название страницы | `Path and URL` | Человекочитаемый заголовок, обычно содержимое или front matter |
| Публичный URL | `/development/path-and-url.html` | Правило permalink генератора и совместимость ссылок |

Эти значения могут совпадать по смыслу, но не обязаны быть одинаковыми. Не следует менять URL только ради косметического переименования исходного файла.

## 2. Базовые правила для нового проекта

- Для новых файлов и каталогов, которые контролируем сами, использовать строчные латинские имена и `kebab-case`: `project-structure.md`, `site-assets/`.
- Использовать понятные слова, а не неочевидные сокращения и случайные идентификаторы.
- Не добавлять числа в начало имён только ради сортировки. Числа оправданы, если они являются смысловым идентификатором или частью устойчивого порядка.
- Не использовать пробелы, управляющие символы и неоднозначные варианты регистра в путях.
- Выбрать единый стиль и применять его последовательно; не переименовывать существующие файлы без причины.
- Не использовать регистр как единственное различие между именами: URL регистрозависимы на уровне веб-адресов, а разные файловые системы могут обрабатывать регистр по-разному.
- Разделять слова в URL дефисами, если нет особого требования другого формата.
- Не включать технические слова вроде `final`, `new`, `latest`, `copy2` в стабильные имена без версионирования или контекста.
- Имена служебных файлов генератора выбирать по его соглашениям; не считать любое имя с подчёркиванием универсальным стандартом.

## 3. Что важно для Jekyll

Jekyll использует имена и каталоги со специальным смыслом: например, `_config.yml`, `_data/`, `_includes/`, `_layouts/`, `_posts/`, `_sass/`. По умолчанию пути, начинающиеся с точки или подчёркивания, не публикуются, если явно не включены. Поэтому:

- Не помещать обычные публичные страницы в каталог с начальным подчёркиванием без явной настройки.
- Локальный `_menu` — наша собственная договорённость, а не встроенная функция Jekyll. Генератор не начнёт автоматически читать этот файл: для него нужна явно реализованная логика.
- Проверять, не совпадает ли новое имя с зарезервированным именем генератора или плагина.
- Учитывать, что имя исходного файла и URL можно развести с помощью `permalink`.

## 4. Имена и адреса в точной копии Oscean

В точной реплике исходные имена оригинала — это данные для сохранения, а не повод немедленно стандартизировать всё под единый стиль. У оригинала есть исторические имена и разные расширения: например, `src/oscean.tal`, `src/lexicon`, `links/main.css`, страницы в `docs/` с `.txt` и `.html`, а в генерируемом сайте — `.html`.

Рекомендация:
- сохранять имя оригинала в архивной копии исходника;
- отдельно фиксировать желаемый URL;
- менять имя только при конкретной необходимости;
- при переименовании проверять ссылки, регистр, относительные пути, RSS, изображения, якоря и перенаправления.

## 5. URL: проверенные рекомендации

Google Search Central рекомендует простые, описательные URL, слова на языке аудитории и дефисы между словами; также предупреждает, что URL чувствительны к регистру. Это рекомендации по понятности и обходу сайта, а не требование SEO-плагина.

Для нашей Jekyll-копии текущий ориентир проекта — URL страниц с расширением `.html`, кроме корневой страницы. Это проектное требование, не универсальная рекомендация всех SSG. Его нужно централизованно задать и проверить после сборки, а не выводить из имени каталога на глаз.

## 6. Предлагаемая политика имён для проекта

| Область | Рекомендация | Исключения |
|---|---|---|
| Новые Markdown-файлы | `lowercase-kebab-case.md` | Имена, копируемые без изменений из оригинала |
| Новые каталоги контента | `lowercase-kebab-case/` | Названия, уже являющиеся частью URL или lexicon оригинала |
| Шаблоны и данные Jekyll | Следовать соглашениям Jekyll (`_layouts`, `_includes`, `_data`) | Собственные служебные имена документировать |
| URL | Явное, стабильное правило; текущая цель — `.html` для страниц | Корень сайта и подтверждённые исключения |
| Файлы ресурсов | Описательные имена, согласованный регистр | Оригинальные ресурсы в режиме точного копирования |

Это предлагаемый стандарт для новых сущностей. Он не означает, что нужно массово переименовать существующие папки или менять опубликованные URL.
