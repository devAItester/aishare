Все немножко не так.
Есть спецификация языка ECMAScript.
В спецификации есть части - которые обязаны быть реализованы единым общзим образом для все.
Есть части, которые демонстрирую алгоритм, при этом сообщается, что конкретная реализация может быть другой, но входящие данные и результаты реализации обязаны совпадать с предложенным алгоритмом.

Agent (v8, spider monkey, etc...) не предоставляет никаких дополнительных API но реализует какую то из версий спецификации.
Дполнительнае API предоставляет HOST среда.

То есть все Agent-ы на уровне реализации одной версии ECMA spec - обязаны давать один и тот же результат. В некоторых случаях обязаны это делать единым образхом. В некоторых слдучаях - могут придумать свой алгоритм. НО - результаты обязаны совпадать.

Вместо ИГОГО:
В Агентах может отличаться реализация, и все сопуствоующее что не рекуглирует спецификация. Например специяикация ECMA не регулирует как должен работать Garbage COllector и должен ли он вообще быть. По этой причине GC в V8 отличается от GC в SpiderMokey.

Спецификация не обьясняет КАК Агент должен реально создавать обьект в памяти. Потому реализация обьектов в V8 и SM разная. Но при этом спецификация настаивает на том, чтобы ВСЕ структуры данных были ссылочными если явно не укзаано другого. В результате и в SpiderMonkey и в V8 типичное число с плавающей точкой - это структура в куче на которую указывает ссылка.


Учитывать сейчас SPiderMonkey в случае кломмерческого интереса - не рационально. Он остает от V8 минимум лет на 5. Как и JSC. По сути V8 сейчас безальтернативен.
